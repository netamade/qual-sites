# 資格問題集ライン：練習用WEBサイト共通仕様 v1（2026-11-10 本人指定）

資格のオリジナル問題集には、**必ず練習用WEBサイトをセットで開発する**。以下を全タイトル共通の必須仕様とする。

## 1. 出題モード（4種）
1. ランダム出題・択一（収録問題全体からランダム）
2. ランダム出題・一問一答
3. 分野別・択一
4. 分野別・一問一答

- 毎日のランダム出題がある（その日の問題として収録問題からランダム表示）
- **選択肢の並びは表示ごとにランダム**にする（同じ問題でも肢の順番が変わる。位置で正解を覚えてしまうのを防ぐため）。択一はランダム・分野別のどちらも対象

## 2. 解答・解説
- 解説は詳細に書き、**根拠条文・根拠情報を明確に明記**する
- 誤りの選択肢については、なぜ違うか（×理由）・どこが違うか（×箇所）を示す
- 各問題に正解率・難易度を表示する

## 3. 学習状況の可視化
- 分野ごとの成熟度を**レーダーチャート**で表示できる
- **次の試験まで○日**のカウントダウン表示（端末の日付から動的に計算し、固定値を埋め込まない）

## 4. 書籍との連動
- 書籍の中に「当該サイトでも練習可能」という案内コンテンツを入れる（サイトと本を相互に送客する）

## 5. デプロイ方針
- **GitHub Pagesは使わない**。無料でセキュアな場所を標準とする
- 標準候補：**Cloudflare Pages**（無料・HTTPS標準・プロジェクト名を無意味な文字列にでき、ドメインから出所を特定されにくい）
- ドメインは画一的・特定可能な名前にしない（プロジェクト名は内容を推測できない文字列にする）

## 6. デザイン
- UIは非常にスタイリッシュでデザイン性の高いものにする（学習の継続意欲につながる見た目を必須要件とする）
- 既存の資格学習サイト（マンション管理士／管理業務主任者）の水準を下限とし、再開位置からの継続、進捗表示などの学習体験も踏襲する

## 適用範囲
資格問題集ラインの全タイトル：第二種電気工事士、マンション維持修繕技術者、消防設備士シリーズ（全8巻）、宅建、マンション管理士、管理業務主任者、社労士、行政書士。

## 7. 開発体制とセキュリティ（2026-11-10 本人指定）
- 実装はコーディングAIを駆使する（Codex／Claude Code／Grok Build／Gemini等）。クロは要件・基本設計・検証を担当する
- 不特定多数が使う公開サイトになるため、**セキュリティを特に重視**する。公開前のセキュリティレビューを完了条件とする（DeFi練習サイトと同じ運用）
- 書籍の問題制作と並行して、少しずつ作る（問題がたまったタイトルから順にサイト化する）
- 設計の原則（基本設計で具体化）：バックエンドを持たない静的サイトとし、学習記録は利用者の端末内（localStorage）に閉じる。個人情報を収集しない

## 8. デプロイ手順の決定（2026-11-10）
- Cloudflare Pagesへのデプロイは **GitHub連携ではなく、ダイレクトアップロード方式**（ビルド済みファイルを直接上げる）とする。公開リポジトリを持たずに済み、ドメインの出所も特定されにくい
- 各AIからの連携・デプロイ作業は、その都度クロが行う。ログイン承認など本人の操作が要る場面では、その都度本人に操作を委ねる
- Cloudflareアカウントは本人のGoogleアカウントで作成済み（2026-11-10 本人申告）

## 9. フォント方針（2026-11-10 本人指定）
- フォントはゴシック体（サンセリフ）で統一し、見やすさを優先する（見出しも明朝系にしない）。資格サイトのスペースも同じ方針とする

## 10. 正解・不正解フィードバックの図形表示（2026-11-10、SKILL QUEST利用者の要望を全サイトへ展開）
- 回答直後のフィードバックは、文章と色だけに頼らず、大きな図形マークを出す：正解＝花丸（朱色）、不正解＝バツ（藍色の太い×）。形と色の両方で区別できるようにする
- マークは外部画像を使わずインラインSVGで描く（全サイト共通のSVG・CSSを使う）。表示仕様の正本は「正解・不正解フィードバックの図形表示 共通仕様 v1」
- 既存サイト（SKILL QUEST／マンション管理士／管理業務主任者／正規表現道場）へも同じマークを反映する

## 10. Cloudflare Pages デプロイ実績（2026-11-10 検証済み）
- テストデプロイ成功：既存のマンション管理士サイト（index.html＋data.js）をプロジェクト「sora-lab-421」へダイレクトアップロード → https://sora-lab-421.pages.dev で公開確認（HTTP 200、data.js 200、_headers のセキュリティヘッダ全て配信確認）
- 手順の要点：①ファイル一式を手元で用意し _headers を同梱 ②**3ファイルをルート直下に格納したZIPで一括アップロード**（ブラウザのファイル指定は1件ずつしかできないため、ZIP方式が正解） ③デプロイ直後は pages.dev の反映待ちで 522 が出ることがある（数分〜10分程度で解消）
- ログインは本人のGoogleアカウント＋スマホ承認が必要な場面がある（本人の承認操作が発生する）
