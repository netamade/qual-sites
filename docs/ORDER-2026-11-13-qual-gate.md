# 発注書：資格サイトに認証コード入力対応を追加する（2026-11-13）

## 目的と方針（本人決定）
- 資格サイトの問題は、今後チェック済みの分からロット単位でデータベース（D1）へ随時投入される。書籍の発売前でも、認証コードを持つ人だけがサイトで問題を見られるようにする。
- コードはタイトル別に発行され、各書籍に記載される。ほかに全タイトル共通のマスターコードが1つある。判定は API 側で行われており、この発注はサイト側（このリポジトリ）の対応のみ。
- SKILL QUEST 側のサイトは対象外。このリポジトリの16サイトだけを変更する。

## API の契約（実装済みの前提として扱うこと）
- 取得先は従来どおり `GET https://sq-questions-api.sola-labo.workers.dev/v1/tools/qual-<slug>/questions`。
- 資格ツールでは、問題が1問以上ある場合、リクエストヘッダ `X-Access-Code: <コード>` が必要。
  - コードが正しい（当該タイトルのコード、またはマスターコード）→ 200 で従来どおり `{tool, generatedAt, questions}` を返す。
  - コードなし・不一致 → **401** で本体は `{"tool": ..., "locked": true, "questionCount": <収録問数>}`（問題は含まれない）。
  - 問題が0問のツールは、コードなしでも 200 で空の questions を返す（コード入力は求められない）。
- CORS は X-Access-Code ヘッダ付きのリクエストを受け付けるよう API 側で対応済み。

## サイト側の実装要件
1. `template/engine.js` の loadData（API取得処理）を拡張し、次を満たすこと。
   - localStorage に保存済みのコードがあれば（キーは既存の storagePrefix 配下に `accessCode` を付ける等、このサイト専用のキー）、最初から `X-Access-Code` ヘッダを付けて取得する。
   - 応答が 401 のときは、問題エリアに**コード入力画面**を表示する。文言には収録問数（questionCount）を含める（例：「このサイトには ◯問 の問題があります。書籍に記載の認証コードを入力してください」）。入力欄と「表示する」ボタンを置く。
   - 入力されたコードで再取得し、200 が返ったらコードを localStorage に保存して通常の問題表示へ進む。401 が返ったら「コードが違います」と表示して再入力できるようにする（保存済みコードが 401 になった場合も、そのコードを消去して入力画面を出す）。
   - 200 で1問以上 → 従来どおり questions を採用。200 で0問・通信失敗・タイムアウト等 → 従来どおり data.js の表示（「問題は順次追加中です」等）を維持する。 `template/build.mjs` で全16サイトを再生成し、生成物（index.html／_headers）を同一 PR に含めること。data.js・デザイン・文言（コード入力画面の新規文言を除く）は変更しない。CSP は変更不要（API への接続先は既に許可済み）。スクリプトが変わるためハッシュは build が自動で再計算する。 既存のセキュリティ設定（CSP の他の要素、各種ヘッダ）は弱めない。

## ローカル検証（PR 本文に結果を書くこと）
実際の API へはダミー問題を保存せず、ブラウザ内で API 応答を差し替えて検証する。
- shobo-4 を対象に：① 401（questionCount=1）→ コード入力画面が出て、収録問数が表示される。② 誤ったコード → 401 のまま「コードが違います」と出て再入力できる。③ 正しいコード（ヘッダ付きで 200・ダミー問題1問を返すよう差し替え）→ 問題が表示され、出題・解答・採点までできる。④ ページを開き直すと、コード入力なしで問題が表示される（localStorage の保存済みコードで取得）。⑤ 0問（200・空）のときは従来の0問表示と一致し、コード入力は出ない。⑥ 通信失敗時は従来表示にフォールバックする。⑦ CSP 違反が0件。
- 他の1サイト（例：takken）でも ①③ を確認する。
- `node template/build.mjs --check` が成功すること。
